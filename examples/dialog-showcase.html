Dialog Component

Modal dialogs and slide-out drawers with HTMX integration for dynamic content loading.

Overview

The dry-dialog component provides both modal dialogs and slide-out drawer panels. Built on the native HTML <dialog> element with HTMX integration for seamless content loading.

Key Features

Modal Dialogs
  • • Centered overlay presentation
  • • Backdrop click to close
  • • ESC key support
  • • Focus trap management
Slide-out Drawers
  • • Four directions: left, right, top, bottom
  • • Smooth slide animations
  • • Configurable width/height
  • • Custom styling support
HTMX Integration
  • • Dynamic content loading from URLs
  • • Server-controlled closing via headers
  • • Form submission handling
  • • Event-driven architecture
Mobile Responsive
  • • Automatically uses modal dialogs on mobile devices (≤768px)
  • • Drawers convert to centered dialogs for better mobile UX
  • • Handles device rotation and viewport changes dynamically
  • • Trigger is now an anchor tag (<a>) instead of button for better accessibility

💡 Two Ways to Customize Drawers

Option 1: Use drawer-class (Recommended)

Just specify styling classes (colors, padding, etc.) and optional width/height. The component automatically handles positioning and animations.

drawer-class="p-8 bg-white shadow-xl w-1/2"

Option 2: Use dialog-class (Full Control)

You must include ALL required classes on a single line (no line breaks). This gives you complete control but is more verbose.

dialog-class="fixed overflow-y-auto transition-transform..."

✨ New Feature: Custom Dimensions

If you include w-* or h-* classes in drawer-class, the component automatically skips the default width/height!

JavaScript API

Programmatic Control

Control dialogs and drawers programmatically using the component's public API.

Hidden Trigger Hidden Drawer Trigger // Get references to components const dialog = document.getElementById('programmatic-dialog'); const drawer = document.getElementById('programmatic-drawer'); // Open and close dialog dialog.open(); dialog.close(); // Open and close drawer drawer.open(); drawer.close(); // Listen for events document.addEventListener('dialog:opened', (event) => { console.log('Opened:', event.detail); }); document.addEventListener('dialog:closed', (event) => { console.log('Closed:', event.detail); });

Custom Events

The component emits custom events you can listen to.

Event When Fired Event Detail
dialog:opened After dialog/drawer opens {mode, url}
dialog:closed After dialog/drawer closes {mode}

API Reference

Attributes

Attribute Type Default Description
url String "" URL to fetch content from
mode String "dialog" "dialog" or "drawer"
direction String "right" Drawer direction: "left", "right", "top", "bottom"
button-class String "" CSS classes for trigger link
dialog-class String "bg-white" CSS classes for dialog/drawer element
dialog-inner-id String "dialog-inner" ID for content container (must be unique)
trigger-id String "trigger" ID for trigger link
trigger-type String "click" HTMX trigger event type

Methods

Method Description
open() Opens the dialog or drawer
close() Closes the dialog or drawer

HTMX Integration

Server Response Headers

Control dialog behavior from your server responses:

HX-CloseDialog: close

Add this header to automatically close the dialog after processing a form submission or action.

HTMX Events

The component listens for these HTMX events:

  • • htmx:afterOnLoad - Checks for close header and redirects

Best Practices

✓ Do

  • • Use unique dialog-inner-id values when multiple dialogs exist on the same page
  • • Set HX-CloseDialog: close header after successful form submissions
  • • Use appropriate drawer directions based on content type (settings from right, navigation from left)
  • • Keep dialog content focused and avoid nesting multiple dialogs
  • • Provide clear close buttons or instructions within loaded content

✗ Avoid

  • • Reusing the same dialog-inner-id for multiple dialogs
  • • Loading very large content that makes the dialog slow
  • • Using drawers for critical actions (prefer centered dialogs)
  • • Forgetting to handle loading states for AJAX content
  • • Overriding backdrop click behavior without providing alternative close methods

Troubleshooting

Content not loading

Check that the URL is correct and the server is returning valid HTML. Open browser DevTools Network tab to inspect the request.

Dialog won't close after form submission

Ensure your server response includes the HX-CloseDialog: close header. Check response headers in DevTools.

Drawer animation not smooth

The drawer uses CSS transitions. Ensure you're not overriding the transition-transform or duration-300 classes.

Multiple dialogs conflicting

Ensure each dialog has a unique dialog-inner-id and trigger-id to prevent ID conflicts.

Styling not applying

Dialog elements are rendered in the top layer. Some CSS properties may not work as expected. Use the dialog-class attribute for custom styling.
