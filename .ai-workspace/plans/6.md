# Issue #6: Add code coverage gate (>= 85%) to GitHub Actions CI

- **URL**: https://github.com/qwigo/dry2/issues/6
- **Created**: 2026-05-31
- **Project Type**: javascript

## Implementation Context

- **Architecture**: The repo has Mocha unit tests under `tests/unit/**/*.test.js`
  (configured by `.mocharc.json`) and `c8` already installed as a devDependency.
  `package.json` exposes `test:unit:coverage` (`c8 --reporter=text --reporter=html
  --reporter=json mocha ...`). There is currently **no** `.github/workflows/`
  directory — this issue adds the first CI workflow plus a committed `c8` config so
  the same 85% gate runs locally and in CI.
- **Key files**:
  - `package.json` — npm scripts; add/adjust a coverage-check script (`scripts` block, lines 16-36).
  - `.c8rc.json` — **new** committed c8 config holding `check-coverage` + 85% thresholds.
  - `.mocharc.json` — existing Mocha config (spec glob `tests/unit/**/*.test.js`); referenced, not modified.
  - `.github/workflows/coverage.yml` — **new** GitHub Actions workflow.
- **Constraints**:
  - `package.json` `engines` requires Node `>=16`; CI pins Node 20 LTS.
  - Do not break the existing `test`, `test:unit`, or `test:unit:coverage` scripts.
  - Gate must fail the build when **any** of lines/statements/functions/branches < 85%.
  - Keep the gate config in a committed file so local and CI runs match.
- **Approach**: Commit 1 adds the committed c8 threshold config and a CI coverage
  script so the gate is reproducible locally; Commit 2 adds the GitHub Actions
  workflow that installs deps, runs the coverage script, and uploads the HTML report.
  Sequential because the workflow (Commit 2) invokes the script/config from Commit 1.
